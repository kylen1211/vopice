## Interfaces

**Consumes**

- T-2 产出的 `Config` 新形态:`template` / `fast_llm_model` / `dual_brain_enabled` / `slow_llm_model: str | None`,以及已合并好的中立字段(`stt_provider` / `stt_model` / `tts_provider` / `tts_voice` / `tts_model`)。**装配层不再自行读环境变量做模板合并**。
- T-2 产出的 fixture `bot_module_dual_brain`(开启态 bot 模块)与既有 `bot_module`(关闭态默认)。
- T-1 产出的 `scenarios.build_system_prompt(template, *, dual_brain_enabled)`(签名不受 2026-08-10 语言段变更影响——模板对象整体传入,语言段取值封装在组合函数内,`bot.py` 无需感知新增的 `language_section` 字段;这正是 ADR-4 所要求的「不触达 bot.py」)。
- `contract/cases.md` §0.4:`AssembledPipeline` 字段变更、开启/关闭两态的管线形状、错误归因判断式、`ignored_sources`、问候种子、观测日志行格式、"无 `on_client_message` 接收端"。
- 既有可复用件(**不新建工厂**):`STT_BUILDERS` / `TTS_BUILDERS`、`build_*` 会话级工厂族。

**Produces**

- `server/bot.py`(改):
  - **`_build_assemblyai_stt`(修订 R2,四条硬约束逐条照办,违反任一条即本卡不通过)**:
    - **B-1** 惰性 import `from pipecat.services.assemblyai.stt import AssemblyAISTTService`(同 deepgram/cartesia 先例),不得提到模块顶部;
    - **B-2 不传任何语言参数**(不传 `language` / `language_code` / `language_detection`),靠 `universal-3-5-pro` 原生 code-switch —— 传 `language_code="zh"` 就退化成中文锁、陪练英语轮直接失效,那正是本轮引入它要解的问题;
    - **B-3 不读 `c.stt_model`**(其默认 `stt-rt-v5` 是 Soniox 档位名),显式 `settings=AssemblyAISTTService.Settings(model="universal-3-5-pro")`;
    - **B-4** `vad_force_turn_endpoint` 用默认 `True`(轮次由本仓 `VADProcessor`/`UserTurnProcessor` 段驱动,与既有 `ExternalUserTurnStrategies()` 一致),**不得**设 `False`;
    - api_key 取既有中立字段 `cfg.stt_api_key`(builder 不感知厂商);`STT_BUILDERS` 新增 `"assemblyai": _build_assemblyai_stt` 一行,既有条目与调用形态不变。
  - **会话级解析(ADR-1)**:`bot(runner_args)` 内以**紧邻两行、其间无 `await`** 执行 `load_dotenv(override=True)` + `session_cfg = load_config()`,再 `run_bot(transport, runner_args, session_cfg)` → `assemble_pipeline(session_cfg, transport)`。硬约束以代码注释固化(注释须写明"中间插入 await 会让并发会话读到半更新的 `os.environ`")。
  - 模块顶层 `load_dotenv(override=True)` + `cfg = load_config()` **保留**,职责收窄为启动预检;**模块级 `cfg` 在生产路径零消费**——`assemble_pipeline` 的实参不得是模块级 `cfg`(可机械核对)。
  - `assemble_pipeline(cfg, transport)` **签名不变**,函数体改造:身份段走 `build_system_prompt(cfg.template, dual_brain_enabled=cfg.dual_brain_enabled)`;快脑模型用 `cfg.fast_llm_model`;`dispatch_llm` 继续用 `cfg.llm_model`(**不得**改成 `fast_llm_model`)。
  - **慢脑开关两态装配**(逐项照 §0.4 关闭态表):关闭态不构造 `slow_llm` / `slow_context` / `slow_pair` / `slow_material_filter` / `sentence_aggregator` / `ProducerProcessor` / `ConsumerProcessor` / `_FastAnswerTap`,对应 `AssembledPipeline` 字段为 `None`;管线退化为**单链,无 `ParallelPipeline`**;`ignored_sources == []`;**保留** `sentinel_filter`、`injector` 与两个派活 tool、`user_llm_enabled=False`。
  - `make_pipeline_error_handler(slow_llm: … | None, slow_material_filter: … | None)`:判断式必须是 `slow_llm is not None and frame.processor is slow_llm`。**本卡最易踩的坑**:漏前半句会让 `ErrorFrame(processor=None)` 被误判为 `slow-brain-failed` 并向客户端推面板消息(SA-14 专测此点)。
  - `seed_greeting_messages(fast_context, slow_context: LLMContext | None)`:`None` 时只种快脑那条。
  - `AssembledPipeline`(M-4):`slow_llm` / `slow_context` / `sentence_aggregator` / `producer` / `consumer` 改 Optional;**新增** `stt`(STT 实例句柄,FR-8 要断言其构造参数)、`template`(本次装配实际使用的模板对象);`tts` 类型标注由具体厂商类放宽为 TTS 基类。
  - **观测日志行**(装配起点,INFO,逐字段照 §0.4 格式):`[scenario] template=<id> stt=<provider>/<model> tts=<provider>/<voice> fast_model=<model> dual_brain=<on|off>`。
  - **不注册** `rtvi.event_handler("on_client_message")`(ADR-7,结构性实现"运行期切模板无接收端")。
- `server/tests/test_scenario_assembly.py`(新增):用例名须含契约锚点关键字 `template_drives`(SA-04)、`dual_brain_off`(SA-05)、`dual_brain_on`(SA-06)、`session_config`(SA-11)、`error_attribution`(SA-14)、`dispatch_unaffected`(SA-15)。
  - **SA-04 的证据形状是硬约束**:必须 `load_config()` 产 `Config` → `assemble_pipeline()` 走完整装配 → 读**真实构造对象**的属性;**禁止**用手工构造 `Config`/`ScenarioTemplate` dataclass 传参绕过 `load_config` 当作本条唯一证据(P55 / FR-8)。
- `server/tests/test_bot.py`(改,**修订 R2 移交本卡**):①`_make_config` 补齐 `Config` 新增字段的构造默认值(白名单第 4 条,**既有断言一字不动**);②新增 assemblyai builder 用例,**用例名须含 `assemblyai`**(契约钉死的 SA-23 锚点)。
- `server/tests/test_dual_brain.py`(改,白名单第 2 条):6 处 `assemble_pipeline(bot_module.cfg, …)` 改用 T-2 的开启态 fixture(`bot_module_dual_brain`),**断言内容不动**。
