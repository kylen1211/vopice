## 验收用例

- **SA-17**(FR-9):`cd /home/ky/git/voice-agent/server && NLTK_DISABLE_IMPORT_SECURITY=1 uv run python -m pytest -q`,退出码 0,`passed` 数 ≥ 70(基线 = 2026-08-10 实测 `70 passed`)。
- **SA-18**(FR-4/FR-9,`manual: true`;**前提**:默认模板 `voice_chat` 不声明 `language_section`,故 2026-08-10 语言段可覆盖变更对这些既有 eval 的输入文本零影响——若复跑发现默认组合文本变了,是 T-1 实现走样,打回而非改 eval):开启态下逐个复跑 `r4_*.yaml` 与 `dual_brain_*.yaml`;R8 故障场景**前置**须先由用户在 `evals/fault.env` 加 `DUAL_BRAIN_ENABLED=true`,且日志必须见 `slow-failed` 才算注入生效——**看不到 `slow-failed` 就是场景静默失效,判失败,不得记通过**。
- **SA-19**(FR-10,`manual: true`):两模板各起一次 bot,text 模式各跑一次新场景,`response` 可被判据区分为不同人设;输出原样落 `baseline/persona-samples.md`。
  - **判据锚点须覆盖语言策略**(2026-08-10 拍板):陪练模板的语言段 = **教学阶段模式(中文主导 + 英语练习素材)**,因此判据除人设风格外,还须能观察到「默认模板全程中文」与「陪练模板中文主导且带英语练习素材」的可区分差异;锚点措辞取自 P-0 确认版文案,不自造。
  - **陪练轮必须含至少一轮英语 audio 输入**(修订 R2,契约 §1 SA-19 + design R-12):text 模式绕过 STT,证不了 AssemblyAI 的中英 code-switch;须以 `user: {modality: audio}` 合成英语语音输入并留存转写——**看不到英语被正确转写就判失败**,不得以「用户自述亲测可用」代替本项目的运行证据。
  - **同轮顺带听 TTS 表现(design R-14,只观察不修)**:TTS 侧仍锁 `Language.ZH`,陪练的英语练习素材会由中文引擎朗读,发音质量未知;本卡用 `-a` 存音频并在 `baseline/persona-samples.md` 写一句主观评价,**若不可接受记 RISKS 另起变更,本卡不得动 TTS**(派单只授权 STT)。
- **交接自检**:eval 复跑前先确认 `judge_factory.judge_llm` 能起(它也调 `load_config()`,会连带校验所选模板的 provider 凭证,design R-6);报缺失就按提示补该 provider 的 key,**不得**为了跑通而改模板或放松校验。

**测试归属(三层)**:本卡只出**行为层**(eval)与**全量回归**。单测层归 T-1/T-2,装配契约层归 T-3;本卡若发现覆盖缺口,记 RISKS 交回,不在本卡补写单测(会踩进他卡独占路径)。
