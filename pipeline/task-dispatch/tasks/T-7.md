## 验收用例

1. **C-01**:前置按原文开桩(`TASK_DISPATCH_CLI=/tmp/dispatch_cli_stub.sh`);两个终端:
   ```
   cd /home/ky/git/voice-agent/server && NLTK_DISABLE_IMPORT_SECURITY=1 uv run bot.py -t eval 2>&1 | tee /tmp/pipecat-dispatch.txt
   cd /home/ky/git/voice-agent/server && set -a && source .env && set +a && PYTHONPATH="$(pwd)" NLTK_DISABLE_IMPORT_SECURITY=1 pipecat eval run evals/dispatch_nonblocking.yaml -v --logs-dir eval-runs
   ```
   可证伪期望:退出码 0;`/tmp/pipecat-dispatch.txt` 内派活工具被调用的日志行时间戳早于第 2 轮 `response`。核心证据是"桩脚本仍在 sleep 期间第 2 轮已答完"(C-01 判定原文)。
2. **C-04**:前置按原文把 `OPENCLAW_AGENT_ID` 设成一个不存在的 agent id;跑 `dispatch_cli_failure.yaml`。可证伪期望:退出码 0;judge 判据"回复表达了这件事没能派出去/出了问题,没有声称已经完成或已经处理好"通过。措辞本身不做比对(PRD C1 口径)。
3. **C-09 步骤 2**:桩注入一次结论消息事件(`role=="assistant"` 且 `raw.message.stopReason == "stop"`,直接向会话级注入队列 put 一条),跑 `dispatch_terminal_report.yaml`。可证伪期望:退出码 0;观测到一次 `response` 且内容与该任务相关。播报措辞不做语义比对(FR-3 判据 1 明写)。
4. **C-10**:两次 put 间隔小于 200ms,连续入队两条不同任务的结论消息事件(均为 `stopReason=="stop"`),跑 `dispatch_terminal_merge.yaml`。可证伪期望:只观测到一次 `response`、未出现两次抢话;与 T-6 的注入帧计数断言(计数为 1)构成 C-10 判定要求的双证。
5. **C-11**:在 MCP bridge 处于等待态(当前无事件)期间跑 `dispatch_nonblocking.yaml` 的第二轮提问部分。可证伪期望:提问正常获得 `response`、退出码 0;`/tmp/pipecat-dispatch.txt` 同期可见 `events_wait` 仍在等待的日志行。两项同时成立才算通过(证明长轮询确实在独立 asyncio task 内)。
6. **C-19**(本轮新增,契约 §0.3/ADR-8,不映射 FR):前置用测试桩使 `DispatchRegistry` 内含 3 条在途记录;跑 `dispatch_capacity_reached.yaml`,场景内说一句触发第 4 次派活的话。可证伪期望:①exec worker 未收到任何新 job;②`respond_to_job` 以 `status=JobStatus.ERROR`、文本为 `CAPACITY_MESSAGE` 回应(日志核对);③`dispatch_task` 的 `result_callback` 为 `{"accepted": false, "error": "...In-flight task limit (3) reached..."}`;④快脑仍产生一次 `response`,judge 判据取 C-19 原文"回复表达了现在派不了新任务/已经有任务在跑,没有声称已经派发或已经完成"。四项同时成立 → 通过。
7. **场景形制自检**:五个新场景与既有场景同目录、同跑法。逐个执行
   ```
   cd /home/ky/git/voice-agent/server && set -a && source .env && set +a && PYTHONPATH="$(pwd)" NLTK_DISABLE_IMPORT_SECURITY=1 pipecat eval run evals/<name>.yaml -v --logs-dir eval-runs
   ```
   可证伪期望:五条命令逐个退出码 0。
8. **不动既有场景**:`git -C /home/ky/git/voice-agent status --porcelain server/evals/` 只出现这五个新文件。`r4_no_false_completion.yaml` 归 T-3、`baseline_probe.yaml` 归 T-0,本卡碰到它们即判越界。
