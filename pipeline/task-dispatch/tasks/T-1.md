## 验收用例

1. **C-00 环境前置门**先跑,三项全满足才继续。原样贴 `openclaw daemon status`、`ss -ltnp | grep 18789`、`openclaw approvals get --json | python3 -m json.tool` 的输出。不满足则本卡结论写"环境未就绪",按下方停下条件处理。
2. **门 A(R-2,MCP 事件样本)**:起 `openclaw mcp serve` stdio 子进程,按 design.md P-04 已验证的握手方式建连,调 `events_wait`;同时派一个能在数分钟内自然结束的任务,触发一次真实的结论消息事件(`role=="assistant"` 且 `raw.message.stopReason == "stop"`)。
   - 可证伪期望:`pipeline/task-dispatch/baseline/mcp-event-sample.json` 存在且 `python3 -m json.tool < pipeline/task-dispatch/baseline/mcp-event-sample.json` 退出码 0;从中能指认出两项——①与 §0.6 生成的 session key 精确相等的任务关联标识字段(`event.sessionKey`);②能判断是否为结论消息的收尾标记字段及取值(`event.raw.message.stopReason == "stop"`)。**不存在**"OpenClaw 原生终态字符串所在字段"这一项——事件通路上读不出任何任务生命周期/终态字符串(D-2)。两项判据逐字写进证据文件正文(T-4 只许依赖这两项,不得读取或臆造第三项,见 §0.8 条 7/条 9)。
3. **门 B(R-4,`cli` 任务记录可查)**:按 §0.6 生成一个 session key `K`,跑
   ```
   openclaw agent --agent <agent_id> --session-key "$K" --message-file /tmp/probe-task.txt --json
   openclaw tasks show "$K" --json; echo "exit=$?"
   openclaw tasks list --runtime cli --json
   ```
   `openclaw agent` 最长阻塞 600 秒(§0.7),探针阶段允许前台等待,也允许 `start_new_session` 起后台后再查,两种用法都要在证据文件里写明实际采用哪种。
   - 可证伪期望:`tasks show "$K"` 退出码 0,返回体 `runtime` 字段值为 `cli`;`tasks list --runtime cli --json` 的 `count` ≥ 1 且列表中含 `K` 对应的记录。
4. **门 C(C-15 的第一次实跑,design.md D-3 缓解)**:对上一步的 `K` 跑
   ```
   openclaw tasks show "$K" --json | python3 -c "import json,sys; d=json.load(sys.stdin); print(repr(d.get('childSessionKey')), repr(d.get('ownerKey')))"
   ```
   - 可证伪期望与判定口径逐字取 `contract/cases.md` C-15:至少一个为具体非空字符串,且与 `K` 可关联(相等,或以 `K` 为前缀/后缀的结构化键)。
5. **停下条件(硬性,不可绕过)**:门 A 或门 B 任一不通过 → 本卡结论写"不通过",立刻停下上报主会话,**不带任何假设往下写解析代码或派发代码**。门 B 不通过意味着 ADR-1 的关联主键整体落空,需回 S2a 重新设计派发形态(`design.md` R-4 原文处置)。门 C 不通过 → 触发 `design.md` D-3 的缓解路径(ADR-1 被否方案重新上桌),同样停下上报,不自行改关联方案。
