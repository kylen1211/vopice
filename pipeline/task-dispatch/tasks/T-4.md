  - pipecat 官方件(venv 实装 1.6.0,符号存在性见 `design.md` P-09):`UIWorker` 的 `@job(name="respond", sequential=True)` / `_run_llm_turn` / `@tool` / `respond_to_job`;`BaseWorker` 的 `job` / `send_job_response` / `create_task` / `cancel_task`;`tool_options`;`FrameProcessor`;`LLMMessagesAppendFrame`;官方 `mcp` SDK 的 `stdio_client` + `ClientSession`(ADR-3:**不经** pipecat `MCPClient`,不注册任何 MCP 工具给任何 LLM)。
- **Produces** —— 全部落 `server/task_dispatch.py`,函数/类级:
  - `async def dispatch_task(params, request) -> None`:快脑侧工具 T1。签名、docstring 首行、`timeout_secs`、`cancel_on_interruption=False`、成功与失败载荷形状按 §0.2;内部动作是 `app_resources.main_worker.job(DISPATCH_WORKER_NAME, payload={"query": request})`。
  - `async def get_task_status(params, lookup=None) -> None`:快脑侧工具 T2,按 §0.2;省略 lookup 时对注册表逐条跑 `CMD_TASKS_SHOW`,**不得**调用无过滤的 `openclaw tasks list`。
  - `class TaskDispatchWorker(UIWorker)`:决策层。自带单个 `reply(self, answer, tasks=None)` 工具;内部次序按 §0.3——**本轮新增步骤 0**:在起 exec job 之前先做在途任务上限检查(`len(DispatchRegistry) + len(tasks) > MAX_INFLIGHT_TASKS` 则整批拒绝,`await self.respond_to_job(answer=CAPACITY_MESSAGE, status=JobStatus.ERROR)`,**不使用第二个 LLM 自己写的 `answer`**,不做部分截断,详见 §0.3 行为约定 1-7 与 ADR-8);未超限时按原次序①对每条 task 起**不等待**的 exec job,②立即 `respond_to_job(answer)`。本期禁用能力清单见 §0.3"本期禁用能力"行。
  - `class OpenClawExecWorker(BaseWorker)`:执行层。`@job(name="dispatch", sequential=False)`;含 session key 生成(§0.6)、任务书临时文件(§0.7 约定 3)、detached spawn(§0.7 约定 4,`start_new_session=True`,不 await 退出)、lookup 轮询上限 30 秒(命中判读靠退出码,JSON 落 stderr,§0.7 约定 6)、注册表写入、`send_job_response`(响应形状 `{"session_key", "lookup", "degraded"}`,**本轮删除 `notify_set` 字段**,随原 FR-4 通知策略整条删除);另在 `on_worker_ready` 用 `self.create_task(...)` 起独立 asyncio task,持有 `openclaw mcp serve` stdio 子进程并循环调 `events_wait`(§0.8 条 1:绝不注册给任何 LLM)。
  - `class DispatchRegistry`:会话级注册表,字段与四条不变量按 `design.md` 数据模型 §2 表(不含任何状态字段、不落盘、工厂构造禁模块级单例、空注册表返回空数组而不报错)。
  - `class _DispatchMaterialInjector(FrameProcessor)`:快脑分支头部注入器。持会话级 `asyncio.Queue`,用 `self.create_task()` 起排空循环,一次取空队列并合并成**一条** `LLMMessagesAppendFrame(run_llm=True)` 推下游(§0.9 合并规则;ADR-4)。
  - `def build_dispatch_stack(cfg, *, cli_override=None)`:会话级工厂(既有 R5 约定:禁模块级单例)。返回持有两个 worker、注册表、注入队列、注入器构造入口与 `app_resources` 的栈对象。**测试开关经关键字参数注入,模块内不读环境变量**(D-003 守法②)。**本轮删除 `skip_notify` 参数**(随 `CMD_TASKS_NOTIFY`/C-13 一并作废,无对象可跳过)。
  - `server/pyproject.toml` 依赖新增 `pipecat-ai[mcp]`(带出 `mcp[cli]>=1.11.0,<2`),`uv sync` 后 `server/uv.lock` 同步更新。
- **不产出**:`server/bot.py` 的任何改动(装配归 T-5);任何测试文件(归 T-6);任何 eval 场景(归 T-7);任何 `server/prompts.py` 改动(归 T-3)。

## 验收用例

1. **本卡自证用的一次性驱动脚本**:允许写 `/tmp/drive_dispatch.py`(**不进仓库**;仓库内的正式单测归 T-6、eval 场景归 T-7),用 `WorkerRunner` 只挂 `TaskDispatchWorker` + `OpenClawExecWorker` 两个 worker、直接发 job,以便在 `bot.py` 装配(T-5)完成之前就跑通下列真机用例。脚本内容与原样输出贴进 `backend-notes.md`。
2. **C-15**(手动接管可达性,FR-5,原 FR-6):按 `contract/cases.md` C-15 步骤跑一次。**提前到本卡完成时就跑,不留到 T-8**(`design.md` D-3 缓解 + 账本 2026-08-08 s2b 待办⑤)。不通过 → ADR-1 的关联主键方案被证伪,停下上报主会话,不自行改关联方案。
3. **在途任务上限行为验证**(本轮新增,契约 §0.3、ADR-8,C-19 的实现层半):用驱动脚本把 `DispatchRegistry` 桩构造为已有 3 条在途记录,再触发第 4 次 `reply(tasks=[...])`(单任务或诱导 fan out 出多条均可,只要 `当前在途数 + len(tasks) > 3`)。可证伪期望:①`exec` worker 未收到任何新 job(计数为 0);②`respond_to_job` 以 `status=JobStatus.ERROR`、文本恰为 `CAPACITY_MESSAGE` 回应,**不使用**第二个 LLM 自己写的 `answer`;③对照组(在途数 < 3 时)按原①②次序正常起 exec job,不受影响。三项同时成立 → 通过。正式的单元测试(T-6)与 eval 场景(T-7,承载 C-19)覆盖同一行为,本条只是本卡的实现自证,不替代它们。
4. **C-02**(断连后任务在 OpenClaw 侧继续,FR-1 判据 2)的进程隔离半:用驱动脚本对已 spawn 的 CLI 进程发 `worker.cancel()`,或直接杀掉驱动脚本进程组,验证 `start_new_session=True` 确实隔开了进程组信号。期望:`openclaw tasks show "$K" --json` 的 `status` 不是 `cancelled`,且仍能继续演进。完整的 `on_client_disconnected` 路径在 T-8 真机复验。
5. **C-04**(派发调用本身失败时经工具报错路径回流)的 job 层半:把 agent id 设为一个不存在的值,期望 exec job 以 `JobStatus.ERROR` 回报且日志含 CLI stderr 首行。eval 层半(快脑仍产生一次 `response` 且未声称完成)归 T-7。
6. **C-08 步骤 1 + 应用层降级**(FR-2 负向):
   ```

   ```
