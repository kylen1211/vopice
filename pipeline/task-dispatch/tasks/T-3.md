1. **C-03**(既有 eval 场景集无新增失败),范围、命令与判定逐字按 `contract/cases.md` C-03;失败集合必须与 T-0 产出的 `pre-change-responses.md` 所对应的那一轮基线一致。
2. **执行次序硬约束**(`design.md` 数据模型 §3,不得颠倒):
   1. **expand**:先改 `server/evals/r4_no_false_completion.yaml` 的 judge 判据。此时 `prompts.py` 尚未改,跑一次该场景:
      `cd /home/ky/git/voice-agent/server && set -a && source .env && set +a && PYTHONPATH="$(pwd)" NLTK_DISABLE_IMPORT_SECURITY=1 pipecat eval run evals/r4_no_false_completion.yaml -v --logs-dir eval-runs` → 期望退出码 0(证明新判据在旧提示词下也成立)。
   2. **migrate**:再删 `CAPABILITY_BOUNDARY_SECTION` 里那一句。
   3. **contract**:复跑 C-03 全集 + 单独复跑 `r4_no_false_completion.yaml`,两次都要求退出码 0。
   可证伪期望:三步各自的命令与退出码原样贴进 `backend-notes.md`。若把第 2 步排到第 1 步之前,第 1 步的 r4 场景会因判据引用已删表述而假失败——出现该失败即判本卡执行次序错误。
3. **最小改动可证伪**:`git -C /home/ky/git/voice-agent diff server/prompts.py` 中,`CAPABILITY_BOUNDARY_SECTION` 块的 `+` 行数为 0(纯格式重排行允许存在,但必须在 notes 里逐行指名);整个 diff 的新增行只有 `INJECT_TASK_TERMINAL_TEMPLATE` 及其注释。出现任何新增的转述内容约束句即判不通过(违反 PRD C1 裁决)。

   cd /home/ky/git/voice-agent/server && python3 -c "import prompts; print('no ability to take real-world actions' in prompts.SYSTEM_PROMPT)"

5. **模板文本逐字一致**:`grep -n "INJECT_TASK_TERMINAL_TEMPLATE" -A 3 server/prompts.py` 得到的模板串,与 `contract/cases.md` §0.9 表格里的模板串逐字符相同(含 `{label}` / `{agent_text}` 两个占位名,**本轮删除 `{status}`**)。判定:把两串分别写进 `/tmp` 文件后 `diff` 退出码 0。
