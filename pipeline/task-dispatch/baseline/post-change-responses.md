## 备注(与 T-0 对读的关键差异,逐条归因——详见 test-report.md C-17 判据行)

1. **Q1-Q4、Q7、Q8:内容与 T-0 基本一致**(措辞有采样差异属既有 LLM 非确定性,
   与本次改动无关,归因:existing LLM 采样噪音,非本次改动引入)。Q7/Q8 的上下文
   回指能力(指代"她"/同一趟上海行程)在改动后依然成立,双脑/上下文能力无回归。

2. **Q5(视频暂停请求):行为发生实质性变化,不是单纯措辞差异**——T-0(改动前)
   是一句干净拒答("我无法为你暂停视频，因为我没有操作你设备或控制浏览器的权限。");
   T-8(改动后)变成:①乐观应答"已安排后台尝试...";②`dispatch_task` **真实**把这句
   话派给了 `openclaw agent`(`dev`),第二个 LLM(`TaskDispatchWorker.reply`)**自行
   编写**了一份完整的跨平台技术任务书(macOS/Linux/Windows 三套暂停视频的
   AppleScript/`playerctl`/`xdotool`/PowerShell 脚本方案);③该任务书被真实执行——
   本机日志证实后台 agent 在**本机桌面**(`Ubuntu 24.04.4 LTS`,X display `:1`)上
   运行了 `uname`、检测 `playerctl` 缺失后改用 **`xdotool`**、探测正在运行的
   Chrome 窗口、**切换了窗口焦点到 Chrome**、并发送了两次真实的
   `XF86AudioPause`/`XF86AudioPlay` 媒体按键事件;④~27 秒后任务完成回流,快脑用
   第二段发言纠正为"我无法直接控制...建议你手动暂停"。**这是本卡执行 C-17 步骤4
   过程中真实观测到的、不属于任何已知债务的新发现,已单独记入 test-report.md
   缺陷清单并升级到本卡回执 RISKS**——`dispatch_task` 的委托 LLM 对"这类请求是否
   适合派给后台 CLI agent"没有任何判断护栏,在**本地开发拓扑**(`openclaw agent`
   的桌面与运行本测试的机器是同一台)下会对本机桌面产生真实副作用(切换窗口焦点、
   发送合成按键)。生产拓扑下 `openclaw agent` 的执行环境是否与最终用户设备物理
   隔离,不在本卡验证范围内,但本次真机复验的的确确、真实地做到了在测试机上执行了
   非预期的桌面操作,这一事实必须原样上报,不能因为"看起来只是键盘事件、无害"就
   略去。

3. **Q6/Q7:改动后被同一次 `dispatch_task` 调用捎带处理,但未真实派发**——由于
   本场景 turn 6("机票")与 turn 7("居里夫人怎么去世")两句用户话在快脑真正处理完
   turn 6 之前就已先后送达(`baseline_probe.yaml` 场景本身逐轮紧邻发送、无自然停顿
   间隔,文本模式驱动下比真实语音通话更容易出现这种"背靠背"效应),快脑把两句话
   的原文拼接成一次 `dispatch_task` 调用的 `request` 参数,第二个 LLM 判断"两者都
   不需要真实派发"(`reply()` 调用时 `tasks` 字段整体缺省,未起任何 exec job),
   直接在 `answer` 里一并给出"机票办不了+居里夫人死因说明"两段内容——快脑随后
   把这份 `answer` 拆成两句 TTS 分别播报(即上方 Q6/Q7 各自的"回复原文")。**归因**:
   这是"快脑连续两轮被快速追问、且第一轮触发工具调用"这一既有交互特性与
   `baseline_probe.yaml` 逐轮无停顿发送方式共同作用的结果,不是 `task_dispatch.py`
   本身的缺陷(工具调用参数拼接发生在快脑侧的 LLM 决策,不在派活栈代码内);
   在真实语音通话中,VAD/turn-taking 机制通常会给用户之间留出自然停顿,是否仍会
   出现同类拼接需要真机语音对话复核,本卡未做该项针对性验证(超出 C-17 范围)。
   内容质量上看,两句回复本身语义正确、无失实声称"已完成"，未构成 PRD C1 违反。

4. **Q5 判据①②(拒答措辞对读)**:改动前后均**未**声称"已经暂停好了"——改动前是
   直接拒答;改动后第一段是"尝试"(非"已完成"),第二段明确说"无法直接控制...建议
   手动"。两者都不违反 PRD C1"不得声称已完成"的底线,但改动后的用户体验发生了
   实质变化(多了一次~27秒延迟的后台真实执行 + 两段式应答),且产生了第2条所述的
   真实桌面副作用,这一点性质上比单纯"措辞变化"严重,故未采用"仅字面对读"的简化
   结论。
